## Implemented External Dependencies & How to Use Them In Tests

The repository already includes concrete implementations for many of the external dependencies referenced by the placeholder tests. Below is a concise mapping and guidance for writing deterministic tests that exercise (or mock) these components.

- **Redis (caching & job queue)**
  - Implementations: `RedisEmbeddingCache` and `RedisTextCache` in `src/InfoDumpManager.Infrastructure/Services/Embeddings` and `.../Services/Caching`; `RedisJobQueue` and `RedisJobTracker` in `src/InfoDumpManager.Infrastructure/Services`.
  - How to use in tests: DI registers an `IConnectionMultiplexer` via `ConnectionMultiplexer.Connect(...)`. For unit tests, mock `IConnectionMultiplexer` and `IDatabase` (StackExchange.Redis) as done in `RedisCacheIntegrationTests.SetAsync_ShouldStoreInRedis`. For lightweight integration tests, run a real Redis instance (or testcontainer) and configure `Redis:Configuration` accordingly.

- **Embedding provider**
  - Implementation: `DeterministicEmbeddingProvider` in `src/InfoDumpManager.Infrastructure/Services/Embeddings`.
  - How to use in tests: DI registers `IEmbeddingProvider` to the deterministic provider by default—use the DI container to resolve it for deterministic vectors, or mock `IEmbeddingProvider` when you need to assert provider call counts or specific vectors.

- **LLM provider (Semantic Kernel)**
  - Implementation: `SemanticKernelProvider` in `src/InfoDumpManager.Infrastructure/Services/LLM` (backed by Microsoft.SemanticKernel). A `Kernel` is registered in DI and configured from `LLM:*` configuration or environment variables.
  - How to use in tests: Prefer mocking `ILLMProvider` for unit tests. For integration tests that exercise the real kernel, ensure `LLM:OpenAI:ApiKey` or `LLM:AzureOpenAI` settings are present in environment or test config; otherwise the kernel will log a warning and not call a remote model.

- **LLM rate limiting**
  - Implementation: `TenantRateLimiter` in `src/InfoDumpManager.Infrastructure/Services/LLM` (uses `PartitionedRateLimiter` and resilience pipeline).
  - How to use in tests: Construct `TenantRateLimiter` with `IOptions<LLMRateLimitOptions>` to set deterministic limits, or mock `ILLMRateLimiter` when exercising code that should bypass rate limits.

- **Resilience / Polly policies**
  - Implementation: `PollyResiliencePolicyProvider` in `src/InfoDumpManager.Infrastructure/Services` exposes `GetLLMPolicy<T>()` and `DatabasePolicy` with retries and circuit breakers.
  - How to use in tests: For unit tests, inject a test `IResiliencePolicyProvider` with no delays or shorter delays. To verify behavior, use small retry/backoff values or assert policy side-effects (e.g., thrown exceptions, circuit open triggers) rather than relying on wall-clock time.

- **Vector store / Postgres + pgvector**
  - Implementation: `PostgreSqlVectorStore` in `src/InfoDumpManager.Infrastructure/Services/Embeddings` and `ApplicationDbContext` configured to `UseVector()`.
  - How to use in tests: Integration tests already include `PostgresTestcontainerFixture` (`tests/.../Fixtures/PostgresTestcontainerFixture.cs`) which boots a Postgres container with `pgvector`. Use that fixture to create `ApplicationDbContext` and exercise `IVectorStore` functions reliably.

- **MinIO (object storage)**
  - Implementation: `MinioStorageService` and `MinioTestcontainerFixture` (in integration fixtures).
  - How to use in tests: Use `MinioTestcontainerFixture` to spin up MinIO for integration tests; inject `IStorageService` from DI or instantiate `MinioStorageService` pointing at the fixture's endpoint.

- **Job queue selection**
  - Implementation: DI selects `RedisJobQueue`/`RedisJobTracker` or `InMemoryJobQueue`/`InMemoryJobTracker` based on config `JobQueue:UseRedis`.
  - How to use in tests: Set `JobQueue:UseRedis=false` in test configuration to get the deterministic in-memory implementations for unit/integration tests that should not depend on Redis.

General test guidance:
- Prefer using the provided deterministic implementations (e.g., `DeterministicEmbeddingProvider`) or the in-memory fallbacks to keep unit tests fast and deterministic.
- For integration tests that must exercise external behavior (pgvector, MinIO), use the included testcontainer fixtures (`PostgresTestcontainerFixture`, `MinioTestcontainerFixture`).
- For time-based or retry/backoff tests (Polly), either inject test-friendly policy providers or assert policy results without waiting real durations.
